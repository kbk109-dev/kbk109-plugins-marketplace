# v1.24.0

> 릴리스 날짜: 2026-10-07

`harness-devkit` 2.0.0 — `harness-dev` 가 PRD 작성부터 세부 계획, 에픽별 feature_list, TC 기반 개발·QA 까지 전 과정을 단계별 서브에이전트로 관리한다.

---

## ⚠️ Breaking Changes

- **`harness-dev` 의 산출물 레이아웃이 바뀐다** — 1.x 의 `docs/harness/{slug}/feature_list.json` + `progress.md` 평면 구조 대신 `BRIEF.md`·`PRD.md`·`PLAN.md`·`PROGRESS.md`·`epics/<NN>/` 구조를 쓴다
  - 마이그레이션: 진행 중이던 1.x 작업은 `legacy` stage 로 계속 재개된다. 새 작업은 2.0 레이아웃으로 시작한다

---

## ✨ Added

- **PRD → PLAN → 에픽 분해 단계** — `prd-writer`·`planner`·`feature-planner` 와, 이를 회의적으로 검토하는 `prd-critic`·`plan-critic`(writer→critic→revise 최대 2라운드). 사용자 승인은 문서 단계에서만 받는다
- **TC 기반 QA** — 에픽마다 개발 전에 `tc-writer` 가 구현 코드를 보지 않고 `TC.md` 를 쓰고, `tc-critic` 이 누락과 타당성을 보수적으로 검토해 확정하면 잠근다. `evaluator` 는 확정 TC 를 PLAN 의 Run & Verify(기동·test·E2E 명령, 승인 전 필수)로 실앱에서 실행하고 그 로그만 증거로 인정한다
- **상태 판정 스크립트** `harness_state.py` — 새 세션이 파일 상태만 보고 현재 단계를 같게 판정한다
- **문서 검증 스크립트** `validate_harness_doc.py` — PRD·PLAN 필수 섹션, Run & Verify, TC 추적성과 잠금 검사
- **기계적 제약 9·10·11** — pass 는 evaluator 만 기록, status 전이 규칙, pass 는 증거 로그 필수 (`schema_version: 2` 파일)
- 에이전트 9개, 산출 문서 템플릿 6개, `CONTEXT.md` 용어집, ADR 0001

## 🔄 Changed

- **generator 와 evaluator 가 별개 서브에이전트가 된다** — 1.x 는 같은 컨텍스트에서 역할만 바꿔 자기평가 편향이 남았다
- **진입 스킬은 얇은 오케스트레이터** — 사용자 대화와 호출 순서 지휘, 상태 파일 갱신만 한다. 에픽이 끝나면 새 세션을 권한다
- **자동 커밋 없음** — 에픽 종료 때 `/simplify` → 회귀 평가 → 사용자 승인 → 커밋. push 는 하지 않는다
- 인터뷰는 `/mattpocock-skills:grill-with-docs`(없으면 같은 방식을 직접 수행)로 하고 결과를 `BRIEF.md` 에 남긴다
- PreToolUse 훅이 디스크의 이전 파일과 비교해 판정하고 호출한 에이전트를 `agent_type` 으로 구분한다. 1회 탈출구와 fail-open 은 그대로다
