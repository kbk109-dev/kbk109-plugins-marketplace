# v1.10.0

> 릴리스 날짜: 2026-08-20

**v1.9.0 의 검색 게이트에 구멍이 있었다.** 매처가 `Grep|Glob` 이고 Bash 의 입력은 `pattern` 이 아니라
`command` 라, `grep -rn listExecTcVersions …` 는 그대로 지나갔다. 이번 릴리스는 게이트를 Bash 까지
넓혀 그 구멍을 막는다.

단순 누락이 아니라 **가장 중요한 경로가 비어 있었다.** 하네스는 어떤 모드에서 모델에게
*"가능한 한 Bash 로 하라 — 검색은 `grep`, `find` 로"* 라고 지시한다. 그런 세션에서 Bash grep 은
우회가 아니라 기본 경로이고, 거기서 게이트는 사실상 무력했다.

---

## ⚠️ 업데이트하면 달라지는 것

**색인이 있는 프로젝트에서 지금까지 되던 `grep` 명령이 차단되기 시작한다.** 심볼처럼 생긴 패턴
(`handleSubmit`·`get_user` 등)을 Bash 의 `grep`·`rg` 로 찾으면 막히고 codegraph 로 안내된다.

막혔을 때 빠져나오는 법은 하나다 — **같은 명령을 그대로 다시 실행하면 통과한다.**
`grep -rn error .` 같은 텍스트 검색과 `ps aux | grep foo` 같은 파이프 뒤 필터는 애초에 걸리지 않는다.

## 🔄 Changed

- **게이트가 `Bash` 도 본다** — matcher 가 `Grep|Glob|Bash` 가 됐다. Bash 명령에서 `grep`·`egrep`·
  `fgrep`·`rg`·`ag`·`ack`·`git grep` 의 검색 패턴을 뽑아 **`Grep` 과 완전히 같은 휴리스틱**에 넣는다.
  판정 기준이 경로마다 갈리면 안 되므로 심볼 판정 함수는 손대지 않았다. `find` 는 뺐다 — 파일명
  검색은 규칙 문서가 Glob 에 맡긴 영역이다.
- **탈출구 키는 도구별로 분리 유지** — `Grep handleSubmit` 과 `Bash handleSubmit` 은 다른 키다.
  합치면 `Grep` 에서 차단당한 모델이 곧바로 `grep -rn` 으로 같은 심볼을 검색해 통과하는 구멍이 생긴다.
  **도구를 갈아타는 것은 "같은 호출의 재시도"가 아니다.**
- 규칙 템플릿·플러그인 README·가이드 7절·`AGENTS.md` 스모크를 Bash 포함으로 갱신했다.

## 기술 상세

### 셸 파싱 — 이 변경의 위험이 전부 모인 곳

`Grep` 은 `pattern` 이 구조화돼 있지만 Bash 는 문자열 하나다. 잘못 파싱하면 **검색과 무관한 셸 명령을
차단**한다. 그래서 전 구간 "확신 없으면 통과"로 짰다.

- **세그먼트의 첫 토큰만** 바이너리로 인정한다. `echo "run grep later"` 나 `$(grep …)` 이 검색으로
  읽히지 않는 이유가 이 제약 하나다.
- **`|` 뒤 세그먼트는 건너뛴다.** `ps aux | grep node` 는 stdout 필터이지 소스 검색이 아니다.
  `&&`·`;` 뒤는 독립 명령이므로 본다.
- **heredoc(`<<`)이 있으면 통째로 통과.** `shlex` 는 heredoc 본문의 단어를 명령과 구분하지 못해
  `cat > f <<'EOF' … && grep …` 이 오탐이 된다.
- **여러 줄 명령은 줄 단위로 나눈 뒤 파싱한다.** `shlex` 는 개행을 그냥 공백으로 보므로, 나누지
  않으면 두 번째 줄부터의 명령이 전부 첫 세그먼트에 흡수돼 사라진다.
- 따옴표 불균형, 명령 치환, `xargs grep` 은 **의도적으로 놓친다.**

### v1.9.0 의 비용 판단을 뒤집는다

v1.9.0 은 "codegraph 실제 호출 여부 추적"을 거부하며 *"셸 경로를 감지하려면 `Bash` 매처가 필요해
모든 프로젝트의 모든 Bash 호출마다 훅 프로세스가 뜬다"* 를 근거로 들었다. 비용 판단 자체는 맞았지만
**Bash grep 이 부차적 경로라는 전제가 틀렸다.** 비용은 그대로 지불하되, Bash 분기가 가장 싼 검사
(명령에 검색 바이너리 이름이 있는가)로 먼저 빠져나가도록 배치했다.

### 검증

- 단위 스모크 **67케이스** 통과 (기존 31 + Bash 36). `-e`·`--regexp=`·`--include` 값 플래그·선행
  환경변수·절대경로·`&&` 뒤·파이프 앞·여러 줄 스크립트까지 차단, 파이프 뒤·heredoc·정규식·공백·
  따옴표 불균형·`codegraph explore` 는 통과.
- **실사용 확인.** v1.9.0 은 개발 세션에 `Grep` 도구가 없어 매처 발화를 확인하지 못한 채 나갔다.
  `Bash` 는 있으므로 이번에는 실제 세션에서 끝까지 확인했다 — `grep -rn has_codegraph_index …` 가
  이유문과 함께 차단됐고, 동일 명령 재실행은 통과했으며, `ps aux | grep …` 은 막히지 않았다.

### 알려진 이슈

- **`Grep|Glob` 매처의 발화는 여전히 미확인이다.** 개발 세션에 그 도구들이 없다. `Bash` 가 뜨는 것을
  확인했으므로 훅 등록 자체는 정상이고, 남은 미지수는 `Grep`·`Glob` 이라는 **이름**뿐이다.
  색인이 있는 프로젝트에서 Grep 도구로 심볼을 검색해 보면 확정된다.
- 이미 `init-agent-rules` 를 돌린 프로젝트는 `.claude/rules/codegraph-search.md` 사본이 이번
  템플릿 변경과 갈라진다. `check-agent-rules` 가 잡고 재실행으로 맞춘다. 설계대로다.
- Notion Tasks DB 매핑 불가 — 이 저장소는 Notion 을 상태 저장소로 쓰지 않는다
  (`release-workflow` 스킬이 *사용자 프로젝트*에서 쓰는 것이다). 릴리스 항목은 git 이력과
  저장소 분석으로 작성했다.
