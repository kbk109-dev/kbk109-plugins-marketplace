# v1.11.0

> 릴리스 날짜: 2026-08-21

**게이트가 코드 검색의 절반을 통과시키고 있었다.** 색인이 있는 실제 프로젝트의 세션 기록에서 검색
패턴 74종을 뽑아 재보니, 코드 검색 23건 중 **12건만** 잡고 있었다. 판정을 "패턴 안에 이름처럼 생긴
토큰이 있는가"로 바꿔 23건 전부를 잡는다.

---

## ⚠️ 업데이트하면 달라지는 것

색인이 있는 프로젝트에서 **지금까지 통과하던 검색이 더 막힌다.** 패턴 **전체**가 식별자가 아니어도,
안에 이름 토큰이 하나라도 있으면 차단된다.

| 이전에는 통과 | 이제 차단 |
|---|---|
| `export const appUser` | ✅ 구조 + 이름 |
| `grep -rn 'enrollRunner\|issueRunnerToken'` | ✅ 묶음 검색 |
| `function collectPropertyNames` | ✅ |
| `CREATE TABLE app_user` | ⚠️ 받아들인 오탐 (아래) |

빠져나오는 법은 그대로 하나다 — **같은 검색을 다시 하면 통과한다.**

`error`·`T-[0-9]+`·`^## 4\.`·`not ok\|✖`·`**/*.ts` 처럼 이름 토큰이 없는 검색은 그대로 통과한다.

## ✨ Added

- **묶음 검색(alternation) 탐지** — `enrollRunner\|issueRunnerToken` 처럼 모델이 심볼 여러 개를 한
  번에 찾을 때 쓰는 형태를 잡는다. 기존 규칙이 놓치던 것 중 가장 체계적인 부류였다.

## 🔄 Changed

- **판정 규칙을 토큰 기반으로 바꿨다** — `is_symbol_shaped`(패턴 **전체**가 식별자) →
  `is_code_search`(패턴 **안에** 3자 이상 + camelCase 경계나 밑줄을 가진 토큰이 있는가).
- **규칙 문서 2절에 경계를 명시했다** — 2절은 "문자열·설정값 검색은 grep 이 맞다"고 말하는데 이제
  그중 일부가 실제로 막힌다. 설명 없이 두면 규칙과 훅이 정면으로 모순된다.
- **상태 파일 휘발성을 문서에 적었다** — OS 가 tmpdir 을 주기적으로 비우므로 ① 정리가 차단과 재시도
  사이에 끼면 같은 검색이 한 번 더 막히고 ② `denied` 배열은 누적 감사 기록이 아니다. README 가
  "재호출은 **반드시** 통과한다"고 단언하고 있었는데 그 경계에서 사실이 아니라 고쳤다.

## 기술 상세

### 규칙을 추측이 아니라 실측으로 정했다

실제 패턴 74종을 코드검색 23 / 비코드검색 51 로 분류하고 후보 규칙을 대조했다.

| 규칙 | 코드검색 23건 중 | 비코드검색 51건 중 오탐 |
|---|---|---|
| 패턴 전체가 식별자 (기존) | 12 | 0 |
| + 심볼 alternation | 17 | 0 |
| **+ 패턴 내 토큰 (채택)** | **23** | **11** |
| + 단일 소문자 단어까지 | 23 | 19 |

마지막 행은 오탐만 8건(`auth`·`origin`·`outcome`) 늘고 새로 잡는 것이 없어 버렸다.

### 오탐을 받아들인 근거

새 오탐 11건은 `CREATE TABLE app_user`·`DATABASE_URL\|skip`·`ports:|image:` 처럼 이름 토큰이 섞인
DB·설정 검색이다. **이전 릴리스들에서 이 비용을 "정당한 검색을 깨뜨린다"고 표현했는데 과대평가였다** —
차단은 복구 가능하고 대가는 재시도 한 번이다. 그 값을 제대로 매기면, 코드 검색의 절반을 통과시키는
규칙을 유지할 이유가 없다.

### v1.9.0 부터 달려 있던 알려진 이슈를 닫는다

세 릴리스에 걸쳐 "`Grep|Glob` 매처의 발화 미확인"이 붙어 있었다. 실측으로 닫았다 — 대상 프로젝트의
도구 호출 **1910건 중 `Grep`·`Glob` 은 0건**이었고 Bash 가 68%였다. **매처가 깨진 것이 아니라 그
환경에서 그 도구들이 쓰이지 않는다.** bypass permissions 모드가 검색을 Bash 로 하라고 지시하기
때문이며, 그래서 v1.10.0 의 Bash 커버리지가 그 환경에서 유일하게 의미 있는 경로였다.

판정 절차는 플러그인 README 의 "훅이 안 뛰는 것 같을 때"에 넣었다 — 세션 기록에서 도구 이름을
집계하는 방식이라 **소급 확인이 되고 설정을 건드리지 않는다.**

### 검증

- 단위 스모크 **90케이스** 통과 (v1.10.1 의 75 + 15). 받아들인 오탐도 명시적 케이스로 고정했다.
- 관측 패턴 74종 재검증 — 코드검색 23/23 차단, 비코드검색 11/51 차단.
- 실사용 — 실제 세션에서 alternation 패턴(`is_code_search\|extract_pattern`)이 차단됐다. 기존
  규칙에서는 통과했을 패턴이다. 재실행 통과·오탐 없음도 함께 확인했다.

### 알려진 이슈

- **차단이 codegraph 호출로 이어지는지는 아직 데이터가 없다.** 지금까지 확인된 것은 "막는다"까지다.
  게이트 도입 이후의 표본이 전부 의도적 테스트라 자연스러운 작업 데이터가 없다 — 시간이 쌓여야
  나온다. 플러그인 README 의 세션 집계로 나중에 측정할 수 있다.
- 이미 `init-agent-rules` 를 돌린 프로젝트의 `.claude/rules/codegraph-search.md` 사본은 이번 템플릿
  변경(2절)과 갈라진다. `check-agent-rules` 가 잡고 재실행으로 맞춘다. 설계대로다.
- Notion Tasks DB 매핑 불가 — 이 저장소는 Notion 을 상태 저장소로 쓰지 않는다. 릴리스 항목은
  git 이력과 저장소 분석으로 작성했다.
