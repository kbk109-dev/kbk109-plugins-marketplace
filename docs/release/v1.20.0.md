# v1.20.0

> 릴리스 날짜: 2026-09-13

스킬 18개 전체의 `description` 을 재작성해 세션당 상시 컨텍스트 고정비를 **7,318 →
2,180토큰(-70%)**으로 줄이고, 이 예산을 `validate-marketplace.sh` 로 기계적으로 강제한다.

---

## 왜 필요했나

스킬 `description` 은 `description`+`when_to_use` 를 통틀어 스킬이 호출되지 않아도 모든
세션의 컨텍스트에 항상 로드된다(공식 상한 1,536자는 넘겨도 목록에서 잘릴 뿐인 soft 상한이라
초과 방지만으로는 이 비용을 줄일 수 없다). 측정해 보니 플러그인 스킬 18개 합계가 14,197자
(한글 3,015자) ≈ 7,318토큰이었고, 그 대부분은 의미상 중복인 한글 굴절 변형이었다 —
`admob-impl` 하나에 `'구현해줘'`/`'적용해줘'`/`'넣어줘'`/`'만들어줘'` 가 따로 들어 있는 식으로,
모델이 이미 하는 형태소 일반화를 열거로 되풀이하며 토큰만 먹고 있었다.

부수적으로 `expo-app-kit:admob-impl` ↔ `admob-impl-harness` 의 트리거 집합이 13개 글자
그대로 겹쳐 라우팅이 프롬프트 문구 운에 좌우되는 문제도 있었다.

## 무엇이 달라지나

- 18개 스킬 `description` 서술부를 영어로 통일하고, 트리거를 아티팩트 파일명(`ADMOB-PLAN.md`
  등)·API 심볼(`recordError`, `logEvent`)·에러 문자열(`fingerprint 불일치`) 같은 고신호
  앵커로 좁혔다. 한글 트리거는 `README.md` "트리거 예" 표에 이미 약속된 문구를 최소 보존
  기준으로 삼았다. 결과: 합계 **6,845자(한글 375자) ≈ 2,180토큰**
- `admob-impl` 을 기본으로, `admob-impl-harness` 는 하네스를 명시했을 때만 뜨도록 양쪽에
  상호 안티트리거를 넣어 라우팅 충돌을 해소했다. 같은 이유로
  `release-plan`/`release-impl` ↔ `fix-plan-impl`, `init-agent-rules` ↔
  `refresh-agent-rules` 에도 안티트리거를 명시했다
- `AGENTS.md` 에 "`description` 작성 규격" 절을 신설했다 — 4부 구조(계약·전제조건·트리거·
  안티트리거), 트리거 우선순위표, 예산표(스킬당 550자/한글 60자, 평균 450자)
- `scripts/validate-marketplace.sh` 에 검사 3개를 추가했다: description 예산(검사 6),
  SKILL.md 500줄 상한(검사 7), README "트리거 예" 표 문구가 description 에 실재하는지
  (검사 8 — 언더트리거 회귀 감시). 검사 2 는 `marketplace.json` ↔ `plugin.json` 의
  `version` 동등까지 비교하도록 넓혔다 — 기존에는 `name` 만 비교해 두 곳이 어긋나도
  통과했다

## 변경 범위

영향받은 플러그인 6개 전부와 `.claude/skills/new-plugin`. 스킬 본문(SKILL.md 의 절차
서술)은 건드리지 않았다 — `description` 프론트매터만 재작성했다.
