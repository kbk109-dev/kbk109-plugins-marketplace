# v1.18.0

> 릴리스 날짜: 2026-09-06

`project-conventions:init-agent-rules` 에 컨텍스트 자동 압축 임계값 설정을 추가한다.
설치 시점에 물어보고("예"면 %를 받는다), 답하면 `--auto-compact-window {0~1 값}` 을
설치 스크립트에 넘겨 대상 프로젝트의 `.claude/settings.local.json` 에
`autoCompactEnabled`/`autoCompactWindow` 를 기록한다. 기본은 미설정 — 아무 것도 물어보지
않으면 지금까지와 동일하게 이 파일을 건드리지 않는다.

---

## ⚠️ 왜 공유 `settings.json` 이 아니라 개인 `settings.local.json` 인가

자동 압축 임계값은 모델·컨텍스트 크기·작업 습관에 딸린 개인 환경 값이지 프로젝트 규약이
아니다. 커밋되는 `.claude/settings.json` 에 쓰면 이 저장소를 클론한 모든 팀원의 개인
`~/.claude/settings.json` 설정을 덮어쓴다 — AGENTS.md 가 `.mcp.json` 재정의를 기각한 것과
같은 논리다. `settings.local.json` 은 gitignore 대상이므로 이 충돌이 구조적으로 발생하지
않는다. 설치 스크립트는 그 파일이 실제로 `.gitignore` 대상인지 확인해, 아니면 경고만
출력한다(`.gitignore` 자체는 고치지 않는다).

## 검토했지만 채택하지 않은 것 — "커밋 후 자동 압축"

원래 요구는 "커밋을 실행하면 커밋 완료 후 compact 자동 실행"이었다. 조사 결과 하네스가
지원하지 않는다:

- 훅의 JSON 출력 스키마에 압축을 발동시키는 필드가 없다
- `PreCompact` 훅은 이미 시작된 압축을 **차단**만 할 수 있다 (요청 아님)
- 모델은 `/compact` 같은 내장 슬래시 명령을 호출할 도구를 갖고 있지 않다
- 자동 압축 설정(`autoCompactWindow`)은 **토큰 임계값**에만 반응한다 — "작업 완료 후"라는
  경계 개념이 없다

그래서 이번에 추가한 것은 그 임계값을 낮추는 옵션 하나뿐이다. 실제 동작은 "작업 도중이든
아니든 컨텍스트가 그 비율을 넘는 순간 그 자리에서 압축"이다.

## 새 CLI 옵션

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/init-agent-rules/scripts/install_agent_rules.py \
  --project-root . \
  --auto-compact-window 0.5 \
  --dry-run
```

| 인자 | 동작 |
|---|---|
| `--auto-compact-window {0<x<1}` | `.claude/settings.local.json` 에 `autoCompactEnabled: true`, `autoCompactWindow: {값}` 기록. 값이 0~1 범위를 벗어나면(예: `50`) exit 2 + "퍼센트가 아니라 비율입니다" 힌트 |
| (생략 시) | 이 파일을 아예 건드리지 않음 — 기본 동작 유지 |

`check-agent-rules` 는 이 파일을 검사하지 않는다 — 커밋되는 정책 산출물(검사 7·8·9)과
달리, 개인 gitignore 파일은 팀원마다 값이 다르거나 아예 없는 것이 정상이기 때문이다.
