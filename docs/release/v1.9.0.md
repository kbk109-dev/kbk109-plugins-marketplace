# v1.9.0

> 릴리스 날짜: 2026-08-20

`project-conventions` 의 codegraph 규칙이 **부탁에서 강제로** 바뀌었다. 심볼처럼 생긴 패턴의
`Grep`/`Glob` 호출을 PreToolUse 훅이 막고 codegraph 로 보낸다. v1.4.0 에서 서브에이전트 프롬프트에
규칙을 심었지만, 심은 것이 여전히 지시문이라 실제로는 codegraph 가 잘 쓰이지 않았다 — 이번에는
검색 도구 호출 자체를 잡는다.

---

## ✨ Added

- **심볼 검색 게이트 훅** — `.codegraph/` 색인이 있는 프로젝트에서 `handleSubmit`·`get_user` 같은
  심볼형 패턴으로 검색하면 차단되고, `codegraph_explore`(MCP) 또는 `codegraph explore`(셸) 호출법을
  안내받는다. 규칙 문서를 읽고 따르느냐와 무관하게 동작한다.
- **색인 판정 공유 모듈** — 두 훅이 `.codegraph/` 를 찾는 경계 탐색을 한 곳에서 쓴다.

## 🔄 Changed

- **훅 허용 조건에 세 번째가 붙었다** — 기존은 "① 조건 미충족이면 무출력 ② 전 구간 fail-open"
  이었는데, 차단하는 훅은 ②의 문면과 충돌한다. **③ 차단한다면 복구 가능할 것**을 더했다.
- **`codegraph-search` 규칙 문서 2절**에 훅과의 관계를 적었다. 2절은 "문자열·설정값·파일명 검색은
  grep 이 맞다"고 말하는데 훅이 grep 을 막으므로, 설명이 없으면 규칙과 훅이 모순으로 읽힌다.
- **훅 실행이 `python3 -B`** 가 됐다. 공유 모듈 import 로 설치 디렉토리에 `__pycache__` 가 쌓이기
  시작했고, 매 호출이 새 프로세스라 바이트코드 캐시는 이득이 없다.

## 기술 상세

### 왜 완화 없이 매번 차단하는가

"세션당 1회"·"N회마다" 같은 완화는 심볼 검색의 일부만 codegraph 로 보낸다. 목적이 "소스 검색은
codegraph 로"인 이상 통과분이 남으면 목적 자체를 놓친다.

그런데도 도구를 막는 훅을 전역 배포할 수 있는 이유는 **차단이 복구 가능**하기 때문이다. 같은
`(도구, 패턴)` 은 에이전트당 한 번만 차단되므로, 동일한 호출을 그대로 다시 하면 반드시 통과한다.
codegraph 가 답하지 못하는 심볼을 grep 으로 확인하는 길이 늘 열려 있고, 훅이 오판했을 때의 최대
대가는 **도구 호출 한 번 재시도**다.

### 패턴 휴리스틱은 일부러 좁다

정규식 메타문자·공백·따옴표·점·슬래시가 없는 순수 식별자이면서 camelCase 경계나 밑줄을 가진
것만 잡는다. `handleSubmit`·`UserService`·`get_user`·`MAX_RETRY` 는 차단, `error`·`TODO`·`foo`·
`use.*State`·`**/*.ts` 는 통과. 두 방향의 실패가 대칭이 아니어서다 — 놓치면 이전과 같을 뿐이지만,
헛발화하면 규칙 문서 2절이 **grep 의 영역이라고 직접 인정한** 검색을 깨뜨린다.

### v1.4.0 의 거부 판단을 뒤집는다

v1.4.0 "설계상 거부한 것"의 두 번째 항목이 정확히 이 훅이다. 거부 사유 2개 중 하나가 무효화됐다.

- ~~"세션당 첫 호출만 막는 상태 관리는 서브에이전트가 부모의 session_id 를 공유해 성립하지 않는다"~~
  → **PreToolUse 페이로드에 `agent_id`·`agent_type` 이 들어온다.** 실측했다: 서브에이전트는 부모와
  `session_id` 를 공유하지만 고유한 `agent_id` 를 받는다. 상태 키가 생겼다.
- "문자열·설정값 검색은 grep 이 맞는데 전부 막으면 정당한 검색까지 깨진다" → **여전히 유효**하며,
  위의 패턴 휴리스틱과 재호출 탈출구로 풀었다.

### 검증

- 단위 스모크 31케이스 통과 — 항상 차단 / 재호출 탈출구 / 에이전트별 독립 상태 / 휴리스틱 /
  fail-open(깨진 JSON·빈 입력·식별자 없음) / 기존 훅 회귀(`updatedInput` 키 보존·멱등성)
- `agent_id` 실측, 그리고 하네스가 `permissionDecision: "deny"` 와 이유문을 존중하는지 실측
- `validate-marketplace.sh` 전 항목 — 신규 훅이 dangling 검사에 실제로 걸리는지 음성 대조 포함

### 버전

`project-conventions` 1.5.0 → **1.6.0**. 나머지 5개 플러그인은 유지. 마켓플레이스
`metadata.version` 1.8.3 → **1.9.0**. 스킬 18개 · 플러그인 6개 유지. 이 저장소는 `package.json` /

### 알려진 이슈

- **`Grep|Glob` 매처의 실제 발화는 확인되지 않았다.** 훅 로직과 차단 출력 계약은 각각 검증했지만,
  매처 문자열이 하네스의 실제 도구명과 맞는지는 개발 세션에 Grep 도구가 없어 시험하지 못했다.
  색인이 있는 프로젝트에서 심볼 검색을 한 번 해 보면 확정된다 — 차단되지 않으면
  `plugins/project-conventions/hooks/hooks.json` 의 `matcher` 를 실제 도구명으로 고치면 된다.
- 이미 `init-agent-rules` 를 돌린 프로젝트는 `.claude/rules/codegraph-search.md` 사본이 이번
  템플릿 변경과 갈라진다. `check-agent-rules` 가 잡고 재실행으로 맞춘다. 설계대로다.
- Notion Tasks DB 매핑 불가 — 이 저장소는 Notion 을 상태 저장소로 쓰지 않는다
  (`release-workflow` 스킬이 *사용자 프로젝트*에서 쓰는 것이다). 릴리스 항목은 git 이력과
  저장소 분석으로 작성했다.
