## 기술 상세

### 대표 파일은 기계적 규칙으로 고른다

셀은 `대표 파일 + 외 N` 형태다. 대표를 무엇으로 하느냐가 표의 값어치를 가른다.

**여러 스킬에 공통으로 등장하는 파일은 뒤로 미루고, 그 스킬 고유 자료를 앞세운다.**
공통 파일은 `evaluator_guide.md` · `generator_guide.md` · `task_schema.json` ·
`golden_example.md` 넷이고, 이걸 대표로 쓰면 세 스킬이 똑같이 `evaluator_guide.md 외 2` 로
보여 변별력이 사라진다. 규칙을 적용하면 `firebase-crashlytics-impl` 은
`report_template.md 외 3`, `harness-dev` 는 `feature_list_template.json 외 3` 이 된다.

`admob-impl-harness` 와 `firebase-analytics-impl` 만 같은 표기(`evaluator_guide.md 외 2`)인데,
이 둘은 실제로 references 구성이 완전히 같다.

### 검증

표를 사람이 손으로 채우면 파일이 늘거나 줄 때 조용히 어긋난다. 생성도 검증도 스크립트로 했다 —
README 표를 **다시 파싱해** 파일시스템과 대조했고, 18개 행 전부에 대해 대표 파일의 실재 여부와
`외 N` 개수 일치를 확인해 **불일치 0건**이다. 전 스킬의 `` `references/...` `` 포인터가
실재 파일을 가리키는지도 함께 확인했다(dangling 0건).

### 버전

플러그인 6개 버전은 **전부 유지**한다 — `expo-app-kit` 1.0.1 · `firebase-observability` 1.0.2 ·
나머지 1.0.0(`project-conventions` 1.5.0). 마켓플레이스 `metadata.version` 만 1.8.2 → **1.8.3**.

`AGENTS.md` 는 *"문서만 고치는 변경은 버전을 올리지 않는다"* 고 정한다. 이 릴리스는 그 규칙대로면
버전 대상이 아니지만, README 의 배지와 릴리스 절이 태그와 짝이라 **표기를 맞추려면 태그가 필요**하다.
설치된 플러그인의 동작은 v1.8.2 와 같다 — 업데이트해도 바뀌는 것이 없다.

스킬 18개 · 플러그인 6개 유지. 이 저장소는 `package.json` / `app.json` 이 없는 플러그인
마켓플레이스라 Expo 빌드 번호는 해당 없음.
