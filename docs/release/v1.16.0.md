# v1.16.0

> 릴리스 날짜: 2026-08-26

`project-conventions` 에서 **codegraph 강제를 전부 걷어낸다.** 켜진 모든 프로젝트에서 발화하던
`PreToolUse` 훅 2개가 사라지고, 이 플러그인은 AGENTS.md 단일 소스화 + git 브랜치 워크플로 규칙만
다룬다. 1163줄이 지워지고 104줄이 들어왔다.

---

## ⚠️ 업데이트하면 달라지는 것

**검색이 더 이상 차단되지 않는다.** `codegraph_search_gate.py` 가 `Grep`·`Glob` 과 Bash 의
`grep`·`rg`·`ag`·`ack`·`git grep` 을 가로채 심볼처럼 생긴 패턴이면 `deny` 하던 동작이 없어졌다.
`.codegraph/` 색인이 있는 프로젝트에서도 마찬가지다.

**서브에이전트 프롬프트에 규칙이 심어지지 않는다.** `codegraph_subagent_guard.py` 가 `Agent|Task`
디스패치를 가로채 `updatedInput` 으로 프롬프트 끝에 붙이던 문단이 없어졌다.

**이 플러그인에 훅이 하나도 없다.** `hooks/` 디렉터리 자체가 사라졌다. v1.9.0 부터 감수해 온
**Bash 매처의 호출당 파이썬 기동 비용(수십 ms)이 없어진다** — `project-conventions` 를 설치한
모든 세션에서 모든 Bash 호출에 붙던 비용이다.

**`codegraph-search` 규칙이 더 이상 설치되지 않는다.** `init-agent-rules` 의
`--codegraph-rule {auto,on,off}` 옵션도 사라졌다. 그대로 주면 `unrecognized arguments` 로 죽는다.

**이미 설치된 사본은 자동으로 지워지지 않는다.** 되돌리려면 손으로 지운다.

```
.claude/rules/codegraph-search.md
.cursor/rules/codegraph-search.mdc
```

그리고 `AGENTS.md` 의 `<!-- >>> agent-rules: codegraph-search >>> -->` ~
`<!-- <<< agent-rules: codegraph-search <<< -->` 마커 블록.

남겨 두어도 **검사는 통과한다** — 규칙 목록에서 빠졌으므로 `check-agent-rules` 가 그 파일을 아예
보지 않는다. 지우지 않는 이유는 설치 스크립트가 어떤 경우에도 규칙을 삭제하지 않는다는 계약을
이 릴리스에서만 깨고 싶지 않아서다. 제거 코드를 새로 넣는 것은 기능 제거의 범위 밖이기도 하다.

- **서브에이전트 가드 훅** (`hooks/codegraph_subagent_guard.py`, 123줄) — 프롬프트 규칙 주입
- **색인 판정 공유 모듈** (`hooks/_codegraph_index.py`, 49줄) — 두 훅이 쓰던 `.codegraph/` 경계 탐색
- **훅 등록** (`hooks/hooks.json`, 26줄) — 내용 전부가 위 두 훅의 `PreToolUse` 등록이었다
- **`codegraph-search` 규칙 템플릿** (86줄) — `.claude/rules/` · `.cursor/rules/` 로 설치되던 본문
- **`--codegraph-rule` CLI 옵션** — 조건부 설치 판정을 뒤집던 스위치

## 🔄 Changed

- **조건부 설치 기계를 함께 제거했다.** `codegraph-search` 가 유일한 선택적 규칙이었으므로
  `RULES` 의 `required` 플래그, `select_rules()`, checker 의 "선택 규칙은 없어도 통과" 분기가
  전부 발화할 수 없는 코드가 됐다. 남겨 두면 다음 사람이 살아 있는 분기로 읽는다.
- **규칙 부재가 이제 항상 실패다.** 규칙이 모두 필수가 됐으므로 `.md`·`.mdc`·마커 블록이 셋 다
  없으면 `check-agent-rules` 가 exit 1 로 보고한다. 전에는 선택 규칙이라 조용히 지나갔다.
- `refresh-agent-rules` 의 `scan_project_facts.py` 가 내던 `codegraph_index` 사실을 뺐다 —
  그 값을 소비할 규칙이 없어졌다.
- 문서에서 훅 설명을 걷어냈다: 플러그인 README 의 "codegraph 를 강제하는 훅 2개" 절(230줄),
  `docs/guide/project-conventions.md` 7절(71줄, 이후 절 번호 재조정), 루트 `README.md`·`AGENTS.md`
  의 언급과 훅 수동 검증 명령 블록.

## 기술 상세

### 왜 "부분 제거" 가 아니라 전부인가

강제는 두 층위였다. 훅(기계적)과 규칙 문서(문서적)다. 훅만 지우면 규칙 문서가 남아 "코드 검색은
codegraph 우선" 을 계속 지시하는데, 그 지시를 뒷받침하던 장치는 없어진 상태가 된다. **부탁으로
돌아가는 것이 아니라, 근거 없는 부탁이 남는다.** 그래서 둘 다 지웠다.

### 발화하지 않는 코드를 남기지 않는다

`required` 플래그와 `select_rules()` 는 "선택적 규칙" 이라는 개념을 위한 것이었고, 그 개념의
유일한 사용자가 `codegraph-search` 였다. 항목만 빼면 함수는 남지만 `if rule["required"]` 가
항상 참이고 `notes` 는 항상 빈 배열이다. 확장점으로 남길 수도 있었지만, 선택적 규칙이 다시
필요해지는 시점에 어차피 조건식을 새로 쓰게 된다 — 그때 넣는 편이 낫다.

### `hooks.json` 을 함께 지워야 하는 이유

`scripts/validate-marketplace.sh` 의 검사 4 는 `${CLAUDE_PLUGIN_ROOT}/hooks/...` 참조를 뽑아
실체 존재를 확인한다. `.py` 만 지우고 `hooks.json` 을 남기면 **dangling 참조로 검증이 실패한다.**
훅 등록이 전부 codegraph 용이었으므로 파일 자체를 지웠고, 검증은 통과한다.

### 검증

- `validate-marketplace.sh` 5개 검사 통과 — dangling 참조 0건
- 설치 스크립트 — `.codegraph/` 가 있는 픽스처에서도 `git-branch-workflow` 만 설치.
  `--codegraph-rule on` 은 `unrecognized arguments` 로 거부
- 검사 스크립트 3케이스 — 정합 설치 exit 0 · `.mdc` 유실 exit 1 · 규칙 통째 부재 exit 1
  (마지막은 선택 규칙 개념이 사라져 새로 실패하게 된 경로)
- `--sync-mdc` 정상, `python3 -m py_compile` 3개 스크립트 통과
- `harness-devkit` 훅은 그대로 무출력 — 이번 변경이 다른 플러그인의 훅을 건드리지 않았음을 확인
- 잔여 `codegraph` 언급 전수 확인 — `CHANGELOG.md` 과거 항목과 `docs/release/v1.5.0`~`v1.12.0`
  뿐이고, 코드·스킬·매니페스트에는 0건

### 버전

`project-conventions` 1.9.0 → **2.0.0**. 설치되던 규칙 하나와 훅 둘이 사라지고 CLI 옵션이
없어지므로 MAJOR 다. 나머지 5개 플러그인은 유지. 마켓플레이스 `metadata.version` 1.15.0 →
**1.16.0** — 마켓플레이스 자체의 구조는 그대로이고 플러그인 하나가 바뀐 것이므로 MINOR 다.

스킬 18개 · 플러그인 6개 유지 (`project-conventions` 의 스킬 3개도 그대로다 — 사라진 것은
규칙과 훅이지 스킬이 아니다). 이 저장소는 `package.json` / `app.json` 이 없는 플러그인
마켓플레이스라 Expo 빌드 번호는 해당 없음.

### 알려진 이슈

- **이미 설치된 프로젝트의 codegraph 규칙 사본은 남는다.** 위 "업데이트하면 달라지는 것" 의
  경로 3곳을 손으로 지워야 한다. 자동 정리 경로는 넣지 않았다.
- **v1.9.0~v1.12.0 이 쌓은 게이트 판정 로직이 통째로 사라진다.** ALL-CAPS 제외, 파이프 뒤 grep
  통과, 따옴표 불균형 처리 같은 경계 사례 대응이 그 안에 있었다. 다시 필요해지면 git 히스토리에서
  꺼내야 한다 — `v1.15.0` 태그 시점의 `plugins/project-conventions/hooks/` 다.
- **`/plugin marketplace update` 는 실행 중인 세션에 반영되지 않는다.** 훅이 사라진 것을 확인하려면
  `/reload-plugins` 또는 세션 재시작이 필요하다. 그 전까지는 이전 세션의 게이트가 계속 발화한다.
- Notion Tasks DB 매핑 불가 — 이 저장소는 Notion 을 상태 저장소로 쓰지 않는다.
