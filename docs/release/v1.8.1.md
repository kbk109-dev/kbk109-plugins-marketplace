## 기술 상세

### 왜 생성 측이 틀린 쪽인가

둘 다 "이름"일 뿐인데 어느 쪽이 정본인지는 자명하지 않다. 근거 셋으로 정했다.

1. `AGENTS.md` 의 plan/impl 표가 산출 문서를 `docs/plan/GA_PLAN.md` 로 명시한다
2. 형제 계획 문서가 전부 대문자다 — `ADMOB-PLAN.md`(55건) · `CRASHLYTICS_PLAN.md`(58건)
3. 무엇보다 **실제로 그 파일을 읽는 `firebase-analytics-impl` 43건이 전부 `GA_PLAN.md`** 다.
   읽는 이름이 사실상의 계약이고, 소비 측을 43건 고치는 것보다 생성 측 7건을 고치는 쪽이
   변경 표면이 작다

수정 후 `plugins/` 와 `AGENTS.md` 전 범위 51건이 모두 `GA_PLAN.md` 다.

### 과거 릴리스 노트는 고치지 않았다

v1.5.0 · v1.6.0 · v1.7.0 · v1.8.0 노트의 `GA_Plan.md` 언급 4건은 **그대로 뒀다.**
그 시점의 사실 기록이므로 고치면 역사가 왜곡된다. 이슈가 네 번 이월됐다는 사실 자체가
이 패치의 근거이기도 하다.

### v1.8.0 노트의 과소 집계 정정

v1.8.0 릴리스 노트는 이 이슈를 *"`plugins/firebase-observability/README.md:25` 에서만"* 이라고
적었다. 실제로는 `firebase-analytics-plan/SKILL.md` 4줄(6건)이 더 있었다. 그 집계는
`plugins/` 하위를 `head` 로 자른 결과였다.

### 기존 사용자 영향

이미 `docs/plan/GA_Plan.md` 를 가진 프로젝트는 대소문자 구분 파일시스템에서 계획 스킬이
기존 파일을 못 찾아 새로 만든다. 아래로 옮기면 된다.

```bash
git mv docs/plan/GA_Plan.md docs/plan/GA_PLAN.md
```

대소문자 무시 파일시스템(macOS APFS 기본 · Windows)에서는 영향이 없다.
