# v1.6.0

> 릴리스 날짜: 2026-08-19

`init-agent-rules` 가 `CLAUDE.md` 를 옮기기 전에 **본문을 다듬는다.** `/init` 초안은 이관되는
순간 단일 소스가 되므로, 200줄을 넘는 분량과 `CLAUDE.md` 역할을 벗어난 절차가 그대로 굳어
이후 모든 세션의 전제가 됐다. 옮긴 뒤에 고치는 것보다 옮기기 전에 고치는 편이 싸다.

---

## ✨ Added

- **이관 전 본문 다듬기 (Step 0.5)** — `init-agent-rules` 가 설치 스크립트를 부르기 전에 본문을
  정규화한다. 기존 Step 0 게이트를 통과한 뒤에만 실행하며, 게이트 실패 시 파일을 하나도 건드리지
  않는 규칙은 그대로다.
  - **행동 가드레일 블록** — 카파시 4원칙(Think Before Coding · Simplicity First · Surgical
    Changes · Goal-Driven Execution)이 전용 섹션으로 넷 다 없으면 10~20줄짜리 짧은 블록을 붙인다.
    원문 전체를 펼치지 않고, 기존 본문을 교체하지도 않는다.
  - **What / How 분리 승인 게이트** — 다단계 절차는 프로젝트 스킬이나 `paths` 규칙으로 내보낼
    후보로 분류하고, **승인 전에는 파일을 하나도 만들지 않는다.** 침묵은 거절이 아니라 대기다.
  - **200줄 예산** — 이관 후 `AGENTS.md` 예상 줄 수를 보여 주고, 초과하면 추가 분리를 제안한다.
- **재작성 규칙 정본** — `references/claude_md_rewrite.md` (187줄). 검출 기준·정본 블록·판정
  목록·승인 표 형식·예산 계산을 여기 모으고 `SKILL.md` 는 가리키기만 한다.
- **개발자용 사용 가이드** — [`docs/guide/project-conventions.md`](../guide/project-conventions.md)
  (358줄). 플러그인 전체(스킬 2 + 훅 1)를 mermaid 도식 6개로 설명한다. 예시는 지어낸 것이 아니라
  **이 저장소에 실제로 설치된 파일**을 인용한다.
- **eval 4건** — 카파시 prepend / skip, 승인 전 신규 파일 0건, 포인터 구조 재실행 시 대상 판정.

## 🔄 Changed

- **설치 스크립트가 `AGENTS.md` 줄 수를 보고한다** — `--dry-run` 은 예상치, 실제 실행은 결과치를
  출력한다. 모델이 손으로 세면 마지막에 붙는 마커 블록이 빠져 어긋나기 때문이다.
  **200줄 초과는 실패가 아니다** — 종료 코드는 바뀌지 않고 설치는 계속된다.
- **200줄이 상한이라는 오해를 문서에서 끊었다** — `CLAUDE.md`·`AGENTS.md` 는 길어도 전부 로드된다.
  잘리는 200줄/25KB 상한은 auto-memory `MEMORY.md` 전용이므로 truncate 는 구현하지 않는다.
- **옵트아웃** — 사용자가 "그대로 옮겨줘" 라고 명시하면 Step 0.5 를 통째로 건너뛴다. 이때도
  설치 보고에는 줄 수가 남아 나중에 다듬을 근거가 된다.

## 기술 상세

### 카파시 블록을 H1 *아래* 에 넣는 이유

설계 문서상 "본문 맨 앞" 이었지만 실제 삽입 위치는 H1 **아래**다. `install_agent_rules.py` 의
`retitle()` 은 첫 비어 있지 않은 줄 하나만 보고 `# CLAUDE.md` → `# AGENTS.md` 로 바꾼 뒤
`break` 한다. H2 블록을 그 위에 얹으면 제목 변환이 조용히 건너뛰어져 이관된 `AGENTS.md` 제목이
`# CLAUDE.md` 로 남는다. **에러가 나지 않으므로 더 나쁘다.** 설치 스크립트를 카파시 블록에
결합시키는 대신 삽입 위치로 풀었다.
