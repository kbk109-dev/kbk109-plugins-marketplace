## ✨ Added

- **`refresh-agent-rules` 스킬** — 프로젝트를 다시 분석해 `AGENTS.md` 를 현황에 맞게 갱신한다.
  `check-agent-rules` 로는 못 잡는 문제를 맡는다. 그 스킬이 보는 것은 **구조**(포인터·마커·
  `.mdc` 바이트 동일)이지 **내용의 사실 여부**가 아니다 — `.md` 에 적힌 `npm test` 가 아직
  존재하는 명령인지는 보지 않는다.
  - **바꿀 게 없으면 파일을 열지 않는다.** 승인도 묻지 않고 확인 범위만 보고한다. 갱신 스킬이
    매번 뭔가를 고쳐야 한다는 압박으로 멀쩡한 문서를 흔드는 것이 가장 흔한 실패다.
  - **삭제만 항목별로 승인받는다.** 추가·수정은 diff 하나로 일괄 승인해도, 사람이 손으로 쓴
    설계 근거를 모델이 "낡았다"고 지우는 것은 되돌리기 어렵다. 삭제 근거에는 사라진 경로나
    바뀐 스크립트명 등 **어느 사실에서 나온 판정인지**를 반드시 붙인다.
  - 고치는 대상은 **`AGENTS.md` 본문 하나뿐**이다. 마커 블록 구간(`init` 소관) · `CLAUDE.md`
    (포인터) · `.claude/rules/*.md` · `.mdc` 는 건드리지 않는다.
- **`scan_project_facts.py`** — 사실 수집을 스크립트가 맡는다. 명령(`package.json` scripts ·
  Makefile · justfile · `scripts/` 디렉터리 · pyproject · Cargo · go.mod · gradle 등
  **언어 무관 best-effort**), 패키지 매니저(lockfile 판정), 툴체인, 디렉터리 트리,
  `.codegraph/` 존재를 JSON 한 덩어리로 낸다. 기본은 **읽기 전용**이고 `--record` 만 파일을 쓴다.
- **상태 파일 `.claude/agent-rules.state.json`** — 마지막 갱신 시점을 외부화한다. **커밋 대상**이다.
  팀원이 각자 다른 기준점을 들면 같은 변경을 몇 번이고 다시 제안하게 된다.
- **사용 가이드에 세 스킬 역할 구분 도식** — `docs/guide/project-conventions.md` 6절.
  구조를 만드는 것 · 구조가 깨졌는지 보는 것 · 내용이 사실과 어긋났는지 보는 것은 다른 문제다.

## 기술 상세

### 이동은 삭제가 아니다

검증 중에 잡힌 결함이다. git 은 파일이 옮겨지면 `D`+`A` 가 아니라 `R` 로 보고하므로 **옛 경로가
`deleted_files` 에 들어오지 않는다.** 그러면 *"핸들러는 `src/legacy/` 에 있다"* 같은 낡은 줄을
고칠 근거가 사라진다. 스캐너가 `renamed_files: [{from, to}]` 를 따로 내고, 문서가 `from` 을
가리키면 **줄을 지우는 게 아니라 `to` 로 고치도록** 규칙에 못 박았다.

같은 검증에서 두 번째 결함도 나왔다 — 매니페스트 없이 `scripts/*.sh` 로 도는 저장소(이 마켓플레이스
자신이 그렇다)에서 명령을 **하나도 못 찾았다.** `scripts/`·`bin/`·`tools/` 스캔을 추가했다.

### 규칙 정본은 하나다

카파시 4원칙·What/How 분리·200줄 예산은 `init-agent-rules` 의
`references/claude_md_rewrite.md` **하나를 정본으로 재사용**한다. 새 스킬에 복제하지 않았다.
정본이 둘이면 반드시 갈라지고 갈라져도 에러가 안 나는데, 그게 이 플러그인이 막으려는 실패
그 자체다 — 자기 자신에게 같은 실수를 하지 않는다.

### 공식 스킬로 대신할 수 없는 이유

`claude-md-management:claude-md-improver` 는 `CLAUDE.md` 를 대상으로 내용을 써 넣는다.
이관된 저장소에서 돌리면 포인터에 본문이 다시 들어가 `check-agent-rules` 검사 3 이 깨지고,
무엇보다 Cursor 가 그것을 못 읽어 두 도구의 지시가 갈라진다.
