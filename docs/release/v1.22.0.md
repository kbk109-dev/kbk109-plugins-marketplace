# v1.22.0

> 릴리스 날짜: 2026-09-14

커밋을 전담 서브에이전트(`project-conventions:commit-agent`, 모델 haiku)에게 위임하는
구조를 도입하고, `main-branch-merge` 스킬을 `release-workflow` 에서 `project-conventions`
로 옮긴다.

---

## 왜 필요했나

메인 에이전트가 매번 커밋 그룹을 나누고 실행하는 데는 값비싼 모델이 필요 없다. 이 절차를
값싼 모델의 서브에이전트로 분리하면 메인 컨텍스트를 아끼고, "변경을 논리 그룹으로 나눠
그룹마다 커밋"하는 규율이 산문이 아니라 서브에이전트의 고정 절차가 되어 컨텍스트 압축에도
사라지지 않는다.

## 무엇이 달라지나

- `project-conventions` 플러그인 루트에 `agents/commit-agent.md`(모델 haiku)를 신설했다 —
  변경을 논리 그룹(생성물–원본 짝, 변경 종류, 디렉토리 경계)으로 나눠 그룹마다 커밋한다
- 프로젝트가 `init-agent-rules --commit-rule on` 으로 옵트인하면
  `.claude/hooks/commit_agent_gate.py`(PreToolUse) 가 메인 에이전트의 직접 `git commit`
  실행을 막고 위임을 지시한다 — `notion_mcp_gate.py` 와 같은 계약(프로젝트가 명시적으로
  옵트인한 정책이라 탈출구 없음, 전 구간 fail-open)을 따른다. `agent_type` 접미사로
  서브에이전트 자신의 호출은 통과시키고, `release: {버전명}` 형태의 릴리스 커밋(원자적
  단일 커밋)은 예외로 통과시킨다
- `init-agent-rules`/`check-agent-rules` 의 설치기·검사기를 규칙별 스크립트·훅 자산 목록으로
  일반화했다 — 새 규칙을 추가할 때 설치·검사 로직을 다시 쓰지 않아도 된다.
  `check-agent-rules` 검사 항목은 9개 → 11개
- `release-workflow` 에서 커밋 지시를 전부 제거하고 `project-conventions:commit-agent`
  위임으로 교체했다 (`release-impl` 4곳)
- **`main-branch-merge` 스킬을 `release-workflow` 에서 `project-conventions` 로 옮겼다** —
  커밋 위임 구조가 `project-conventions` 에 생기면서 릴리스 커밋 예외 처리도 그 플러그인이
  함께 관장하는 편이 응집도가 높다

## 변경 범위

영향받은 플러그인 2개: `project-conventions`, `release-workflow`. `AGENTS.md` 와
`.claude/skills/new-plugin/SKILL.md` 도 이번 구조(플러그인 루트 `agents/` 는 실제
서브에이전트만, 조건부 훅 예외 목록)에 맞게 개정했다.
