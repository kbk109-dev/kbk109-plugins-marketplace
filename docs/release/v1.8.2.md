## 기술 상세

### 왜 하필 산출 문서 템플릿인가

두 스킬에서 덜어낼 후보는 여럿이었다. 산출 문서 템플릿을 고른 이유는 **분량이 가장 크면서
필요한 시점이 가장 좁기** 때문이다 — 둘 다 Phase 3, 즉 문서를 실제로 쓰는 단계에서만 읽는다.

반대로 남긴 것들이 기준을 보여준다. `admob-plan` 의 Five Agents(69줄)나
`firebase-crashlytics-impl` 의 Hard Gate·기계적 제약은 적지 않은 분량이지만 **스킬 전체의
동작을 규정**한다. 매 호출에 필요한 것은 본문에 남는다.

### 유실 검증

분리는 되돌리기 어려운 편집이라, 옮겼다는 주장만으로는 부족하다. 원본과
(분리 후 본문 + `references`) 를 **줄 단위로 대조해 누락 0건**을 확인했다.
릴리스 검증에서는 전 스킬의 `` `references/...` `` 포인터가 실재하는 파일을 가리키는지도
확인했다(dangling 0건).

### 포인터는 본문 언어를 따른다

`admob-plan` 은 본문이 영어, `firebase-crashlytics-impl` 은 한국어다. 각각의 언어로 포인터를
썼고, 이 저장소의 기존 형태(`**xxx:** references/yyy.md 참조`)를 그대로 따랐다.
`harness-dev` 가 쓰는 방식이기도 하다.
