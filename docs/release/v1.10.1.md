# v1.10.1

> 릴리스 날짜: 2026-08-21

**게이트의 동작은 v1.10.0 과 같다.** 업데이트해도 차단되는 것과 통과하는 것이 달라지지 않는다.
바뀐 것은 두 가지다 — "훅이 안 뛰는 것 같다"를 추측 대신 **측정**으로 답할 수 있게 된 것, 그리고
도구 이름이 어긋나도 아무 신호가 없던 구조를 없앤 것.

## 🔄 Changed

- **훅에서 도구 이름 목록(`SEARCH_TOOLS`)을 제거했다** — 이름은 이제 `hooks.json` 의 matcher
  한 곳에만 있다. 훅은 이름 대신 **입력 모양**으로 판단한다: `Bash` 는 `command` 를 파싱하고
  (셸은 파싱해야 패턴이 나오므로 유일한 예외), 그 밖에는 `tool_input` 에 `pattern` 문자열이 있으면
  검색으로 본다. 부수 효과로, 훅이 모르는 검색 도구라도 matcher 가 보내주기만 하면 그대로 잡힌다.
- **플러그인 README 에 "훅이 안 뛰는 것 같을 때" 절을 신설했다** — 상태 파일 → 도구명 실측 →
  `claude --debug` 순서.
- **`AGENTS.md` 명령 블록에 상태 파일 확인을 넣었다** — 게이트가 실제로 무언가를 막았는지에 대한
  유일한 증거이고, 도구 이름이 접두어로 붙어 어느 경로가 잡혔는지까지 읽힌다.

## 기술 상세

### 왜 이름을 한 곳으로 줄였나

v1.10.0 의 Bash 경로는 실사용에서 확인됐다 — 다른 프로젝트의 상태 파일에
`{"denied": ["Bash listExecTcVersions"]}` 가 남았다. 그런데 같은 세션에서 Grep 도구가 쓰인 정황이
있는데도 `Grep …` 항목은 없었다. **매처의 도구 이름이 틀리면 훅은 에러 없이 그냥 안 뛰기 때문에**
"이름이 틀렸다"와 "그 도구를 안 썼다"를 구별할 방법이 없었다.

이름이 `hooks.json` 과 훅 코드 **두 곳**에 있으면 둘 다 맞아야 동작하는데, 어긋나도 아무 신호가
없다 — matcher 가 새 이름을 잡아도 훅이 조용히 통과시킨다. 같은 실패를 한 번 더 만드는 구조라
하나로 줄였다.

### 부딪힌 것 — zsh 글롭

`cat "$D"/*.json 2>/dev/null` 은 zsh 에서 매칭되는 파일이 없으면 **명령 전체가 중단된다.**
`2>/dev/null` 로 막히지 않는다 — 실패가 셸의 글롭 확장 단계에서, `cat` 이 실행되기도 전에
일어나기 때문이다. 문서의 예제는 `ls` 로 존재를 먼저 확인하는 형태로 적었다.

### 검증

- 단위 스모크 **75케이스** 통과 (v1.10.0 의 67 + 이름 비의존 8). 새 케이스는 `SearchFiles`·`Ripgrep`
  처럼 훅이 모르는 이름이라도 `pattern` 이 심볼형이면 차단되고, `Edit`·`Agent`·`Read` 처럼
  `pattern` 이 없으면 통과하는 것을 확인한다.
- 실사용 재확인 — 차단·탈출구·오탐 없음·상태 파일 기록까지 실제 세션에서 확인했다.

### 버전

`project-conventions` 1.7.0 → **1.7.1**. 나머지 5개 플러그인은 유지. 마켓플레이스
`metadata.version` 1.10.0 → **1.10.1**. matcher 를 건드리지 않아 사용자 동작 변경이 없으므로
MINOR 가 아니라 PATCH 다 — v1.10.0 이 MINOR 였던 기준(사용자의 기존 `grep` 이 새로 차단됨)을
그대로 적용한 결과다.

스킬 18개 · 플러그인 6개 유지. 이 저장소는 `package.json` / `app.json` 이 없는 플러그인
마켓플레이스라 Expo 빌드 번호는 해당 없음.

### 알려진 이슈

- **`Grep|Glob` 매처의 발화는 여전히 미확인이다.** 이번 릴리스는 그것을 *측정할 수단*을 만든 것이지
  답을 낸 것이 아니다. 플러그인 README 의 "훅이 안 뛰는 것 같을 때" 절차로 실제 도구명을 확인한 뒤,
  다르면 matcher 를 교정해야 한다.
- 이미 `init-agent-rules` 를 돌린 프로젝트의 `.claude/rules/codegraph-search.md` 사본은 v1.10.0 의
  템플릿 변경과 갈라진 상태 그대로다. `check-agent-rules` 가 잡고 재실행으로 맞춘다.
- Notion Tasks DB 매핑 불가 — 이 저장소는 Notion 을 상태 저장소로 쓰지 않는다
  (`release-workflow` 스킬이 *사용자 프로젝트*에서 쓰는 것이다). 릴리스 항목은 git 이력과
  저장소 분석으로 작성했다.
