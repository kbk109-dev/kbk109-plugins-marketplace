# PLAN: {제품 이름}

승인된 PRD 를 구현 가능한 단위로 쪼갠 계획이다. 기술 선택·API·패키지 버전은 기억으로 쓰지 않고
context7 이나 WebSearch 로 확인한 출처를 `기술 검증` 에 남긴다.

## 아키텍처
구성 요소, 데이터 흐름, 주요 기술 선택과 그 이유. 기존 코드베이스가 있으면 그 구조를 존중하고
어떤 파일·모듈이 영향받는지 적는다. PRD 요구사항(R#)이 어디서 충족되는지 매핑한다.

## 에픽
에픽은 독립적으로 검증·종료할 수 있는 단위다. 행 형식을 지킨다 (`NN-slug`, 소문자·숫자·하이픈).

## Run & Verify
QA 는 여기 적힌 명령을 실제로 실행한 로그만 증거로 인정한다. 세 줄 모두 실제로 실행 가능한
명령이어야 한다 (`TBD`·`N/A` 불가). E2E 도구가 없으면 도입을 첫 에픽에 넣는다.

- start: `<앱을 띄우는 명령>`
- test: `<단위·통합 테스트 명령>`
- e2e: `<실제 앱을 구동해 흐름을 검증하는 명령>`

## 기술 검증
확인한 사실과 출처 (라이브러리 버전, API 시그니처, 플랫폼 제약). 확인하지 못한 것은 리스크로.

## 리스크
일정·기술 리스크와 완화책, 막혔을 때의 대안.
