# PRD: {제품 이름}

실제로 출시할 수 있는 제품의 요구사항 문서다. 모든 주장은 BRIEF.md 의 결정이나 확인 가능한
출처에 닿아야 한다. 근거 없는 수치·경쟁사 주장은 쓰지 않는다 — 모르면 `열린 질문` 으로 보낸다.
용어는 대상 프로젝트의 `CONTEXT.md` 용어집을 따른다.

## 문제
누가, 어떤 상황에서, 무엇 때문에 불편한가. 지금은 어떻게 해결하고 있고 왜 부족한가.

## 사용자
핵심 사용자 유형과 그들이 이 제품을 쓰는 맥락. 주 사용자 하나를 지목한다.

## 목표와 비목표
- 목표: 이번 마일스톤이 끝나면 참이어야 하는 것 (관찰 가능하게)
- 비목표: 이번에 하지 않는 것과 그 이유

## 사용자 시나리오
주요 흐름을 단계로. 정상 경로 하나와, 실패·빈 상태·권한 없음 같은 대표 예외 경로.

## 요구사항
`R1`, `R2` … 번호를 붙인다. 각 항목은 검증 가능한 문장이어야 한다 (PLAN·TC 가 이 번호를 추적한다).
우선순위(must/should/could)를 적는다.

## 성공 지표
어떻게 성공을 판정하는가. 측정 방법과 기준값. 기준값의 근거가 없으면 "미정 — 열린 질문 Q#".

## 리스크와 가정
기술·시장·일정·데이터 리스크와, 틀리면 계획이 바뀌는 가정. 각각 어떻게 확인할지.

## 열린 질문
`Q1`, `Q2` … 아직 모르는 것. 비어 있으면 "없음" 이라 쓰지 말고 왜 없는지 한 줄을 적는다.
