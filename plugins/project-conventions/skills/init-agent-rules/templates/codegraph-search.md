# 코드 검색은 codegraph 로

이 프로젝트는 codegraph 색인(`.codegraph/`)을 갖고 있다. 코드를 찾을 때 따르는 절차다.

## 1. 코드 검색 진입점

- 심볼의 위치·구조·호출 관계를 알아야 할 때는 grep·find·파일 열람보다 **codegraph 를 먼저 실행한다.**
  - MCP 도구가 있으면: `codegraph_explore`
  - 없으면 셸에서: `codegraph explore "<심볼명 또는 질문>"`
- 질의에 파일명이나 심볼명을 넣으면 줄 번호가 붙은 현재 원본이 그대로 돌아온다.

한 번의 호출로 관련 심볼의 원본과 그 사이 호출 경로까지 함께 온다. grep 이 따라가지 못하는 동적
디스패치 구간이 여기 포함되므로, "grep → 파일 열람 → 다시 grep" 반복을 한 번으로 줄이는 게 목적이다.

## 2. 그래도 grep 이 맞는 경우

- 문자열 리터럴·설정값·주석처럼 심볼이 아닌 텍스트를 찾을 때
- 파일명 패턴으로 훑을 때 (Glob)
- 파일과 줄 위치를 이미 아는 단일 확인

codegraph 는 심볼 그래프다. 텍스트 검색까지 이걸로 우회할 필요는 없다.

## 3. codegraph 를 호출할 수 없을 때 — 경고를 띄우고 계속한다

색인이 없거나(`.codegraph/` 부재), MCP 서버가 연결되지 않았거나, `codegraph` 명령이 없을 수 있다.
이때 **조용히 grep 으로 넘어가지 않는다.** 다음 한 줄을 출력한 뒤 grep·Glob 으로 진행한다:

> ⚠️ codegraph 를 호출할 수 없어 grep/Glob 으로 검색합니다 — 원인: {색인 없음 | MCP 미연결 | 명령 없음}

멈추지 않는 이유: 검색은 대개 더 큰 작업의 중간 단계다. 여기서 멈추면 작업이 통째로 막힌다.
그렇다고 조용히 넘어가면 검색 품질이 떨어진 것을 사용자가 모른 채 결과만 받는다 — 경고 한 줄이
그 사실을 드러낸다.

## 4. 색인이 없어서 실패했다면

`codegraph init` 을 제안한다. **승인 없이 실행하지 않는다** — 색인 생성은 시간이 걸리고 저장소에
디렉터리를 만든다. 색인을 만들지 여부는 사용자의 판단이다.
