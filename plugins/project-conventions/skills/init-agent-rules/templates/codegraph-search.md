# 코드 검색은 codegraph 로

이 프로젝트는 codegraph 색인(`.codegraph/`)을 갖고 있다. 코드를 찾을 때 따르는 절차다.

## 1. 코드 검색 진입점

- 심볼의 위치·구조·호출 관계를 알아야 할 때는 grep·find·파일 열람보다 **codegraph 를 먼저 실행한다.**
  - MCP 도구가 있으면: `codegraph_explore`
  - 없으면 셸에서: `codegraph explore "<심볼명 또는 질문>"`
- 질의에 파일명이나 심볼명을 넣으면 줄 번호가 붙은 현재 원본이 그대로 돌아온다.

한 번의 호출로 관련 심볼의 원본과 그 사이 호출 경로까지 함께 온다. grep 이 따라가지 못하는 동적
디스패치 구간이 여기 포함되므로, "grep → 파일 열람 → 다시 grep" 반복을 한 번으로 줄이는 게 목적이다.

## 2. 그래도 grep 이 맞는 경우

- 문자열 리터럴·설정값·주석처럼 심볼이 아닌 텍스트를 찾을 때
- 파일명 패턴으로 훑을 때 (Glob)
- 파일과 줄 위치를 이미 아는 단일 확인

codegraph 는 심볼 그래프다. 텍스트 검색까지 이걸로 우회할 필요는 없다.

**단, 심볼처럼 생긴 패턴의 Grep/Glob 은 훅이 막는다.** `project-conventions` 플러그인이 켜져 있으면
정규식 메타문자·공백 없이 camelCase 경계나 밑줄을 가진 패턴(`handleSubmit`·`get_user` 등)은 차단되고
codegraph 로 안내된다. 위 목록의 텍스트 검색(`error`·`TODO` 같은 단일 단어, 정규식, `**/*.ts` 류 glob)은
휴리스틱에 걸리지 않아 그대로 통과한다.

차단당했는데 **정말 텍스트 검색이었거나 codegraph 로 답이 나오지 않으면, 같은 호출을 그대로 다시 한다 —
동일한 패턴의 재호출은 반드시 통과한다.** 이 절과 훅이 모순돼 보이지 않는 이유가 이것이다. 훅은 기본
경로를 codegraph 로 바꿀 뿐이고, 이 절이 말하는 grep 의 영역은 재호출 한 번으로 그대로 열려 있다.

## 3. codegraph 를 호출할 수 없을 때 — 경고를 띄우고 계속한다

색인이 없거나(`.codegraph/` 부재), MCP 서버가 연결되지 않았거나, `codegraph` 명령이 없을 수 있다.
이때 **조용히 grep 으로 넘어가지 않는다.** 다음 한 줄을 출력한 뒤 grep·Glob 으로 진행한다:

> ⚠️ codegraph 를 호출할 수 없어 grep/Glob 으로 검색합니다 — 원인: {색인 없음 | MCP 미연결 | 명령 없음}

멈추지 않는 이유: 검색은 대개 더 큰 작업의 중간 단계다. 여기서 멈추면 작업이 통째로 막힌다.
그렇다고 조용히 넘어가면 검색 품질이 떨어진 것을 사용자가 모른 채 결과만 받는다 — 경고 한 줄이
그 사실을 드러낸다.

## 4. 색인이 없어서 실패했다면

`codegraph init` 을 제안한다. **승인 없이 실행하지 않는다** — 색인 생성은 시간이 걸리고 저장소에
디렉터리를 만든다. 색인을 만들지 여부는 사용자의 판단이다.

## 5. 서브에이전트에도 적용된다

이 규칙은 메인 세션만의 것이 아니다. `Agent`(구 `Task`) 도구로 띄운 서브에이전트에도 그대로
적용된다. **서브에이전트로서 이 문서를 읽고 있다면 위 1~4절은 나에게 적용되는 것이다.**

서브에이전트를 따로 언급하는 이유는 이쪽이 조용히 새기 때문이다. 서브에이전트는 사용자 프롬프트로
시작하지 않으므로 `UserPromptSubmit` 계열 훅(codegraph 가 설치하는 `codegraph prompt-hook` 등)이
**구조적으로 절대 발화하지 않는다.** 프로젝트 지시를 상속하는지도 보장되지 않는다. 그래서 메인
세션은 codegraph 를 쓰는데 서브에이전트만 grep 부터 잡는 상태가 만들어진다.

`project-conventions` 플러그인이 켜져 있으면 `PreToolUse` 훅이 서브에이전트 프롬프트에 이 규칙의
요지를 자동으로 덧붙인다. 내가 쓴 것보다 프롬프트가 길어 보이면 그것이고, 프롬프트에 이미
`codegraph` 가 들어 있으면 덧붙이지 않는다.

**훅이 없는 환경 — Cursor, 플러그인 미설치 — 에서는 직접 붙인다.** 코드를 찾거나 이해하는 일이
포함된 서브에이전트 프롬프트에 아래를 넣는다:

> 이 프로젝트는 codegraph 색인을 갖고 있다. 심볼의 위치·구조·호출 관계를 찾을 때는 grep 보다
> `codegraph_explore`(MCP) 또는 `codegraph explore "<질문>"`(셸)을 먼저 쓴다. 문자열·설정값·파일명
> 패턴은 grep 이 맞다. codegraph 를 호출할 수 없으면 조용히 넘어가지 말고 경고 한 줄을 남긴 뒤
> grep 으로 진행한다.

훅이 넣는 블록과 이 인용문은 **일부러 길이가 다르다.** 훅이 넣는 쪽은 아무 맥락 없는
서브에이전트도 혼자 이해해야 해서 더 길고, 이쪽은 사람이 손으로 옮겨 붙이는 용도라 요지만 담았다.
둘을 바이트 단위로 맞추려 하지 말 것 — 사본이 아니다.
