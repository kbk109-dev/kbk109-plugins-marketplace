# 이관 전 본문 다듬기 — 재작성 규칙 정본

`SKILL.md` 의 **Step 0.5** 가 이 문서를 따른다. 대상은 이관될 본문 하나뿐이다 —
`CLAUDE.md`, 또는 이미 포인터 구조인 프로젝트에서 재실행할 때는 `AGENTS.md`.
`.claude/rules/*.md` 와 `.cursor/rules/*.mdc` 는 설치 스크립트의 것이므로 **모델이 건드리지 않는다.**

## 왜 다듬고 옮기는가

`/init` 이 만든 초안은 이관 순간 SSoT 가 된다. 초안의 결함 — 200줄을 넘는 분량, `CLAUDE.md`
역할을 벗어난 다단계 절차, 행동 가드레일 부재 — 이 그대로 굳으면 이후 모든 세션이 그것을
전제로 돌아간다. 옮긴 뒤에 고치는 것보다 옮기기 전에 고치는 편이 싸다.

### 200줄은 목표이지 상한이 아니다

Anthropic 공식 가이드가 권하는 목표 분량이다. **글자 200자가 아니라 파일 전체 200줄**이다.

넘겼다고 잘리지 않는다. `CLAUDE.md`·`AGENTS.md` 는 길어도 전부 로드된다. 잘리는 200줄/25KB
상한은 auto-memory 의 `MEMORY.md` 전용이다 (<https://code.claude.com/docs/en/memory>).

그러므로 **뒷부분을 truncate 하지 않는다.** 200줄은 토큰 예산과 준수율을 위한 목표이고,
초과는 "더 자를 것을 찾아보라"는 신호이지 실패가 아니다. 설치 스크립트도 초과를 보고만 하고
설치를 계속한다.

## 1. 카파시 4원칙 검출

다음 네 원칙이 **전용 섹션**으로 **넷 다** 있으면 아무것도 하지 않는다 (skip).

| 영문 제목 | 한글 제목 |
|---|---|
| Think Before Coding | 생각 먼저 |
| Simplicity First | 단순함 우선 |
| Surgical Changes | 외과적 수정 |
| Goal-Driven Execution | 목표 주도 실행 |

영문 네 제목이 있어도 되고 한글 네 제목이 있어도 된다. 섞여 있어도 넷을 모두 덮으면 충족이다.

**"전용 섹션"이란** 마크다운 헤딩(`## Simplicity First`) 또는 번호 목록의 항목명
(`2. **단순함 우선** — …`) 으로 그 원칙이 이름 붙어 있는 것이다. 본문 어딘가에 비슷한 취지의
문장이 흩어져 있는 것은 충족이 아니다 — 이름이 붙어 있어야 모델이 그 항목을 지목해 따를 수 있다.

넷 중 하나라도 전용 섹션으로 없으면 **불완전**이다. 이때는 아래 블록을 prepend 한다.

**이미 있는 비슷한 문장을 합치거나 지우지 않는다.** 짧은 블록을 위에 두고 기존 본문은 그대로
아래에 둔다. 원칙이 두 번 언급되는 것은 손실이 아니지만, 사용자가 쓴 문장을 모델이 "중복"으로
판정해 지우는 것은 손실이다.

## 2. 카파시 짧은 블록 (정본)

아래 텍스트를 **그대로** 넣는다. 실행 시 임의로 늘리지 않는다 —
원문(약 65줄)을 여기에 펼치는 것이 이 블록이 막으려는 바로 그 일이다.

```markdown
## Behavioral Guidelines (Karpathy)

세션마다 지키는 행동 가드레일. 프로젝트 규칙보다 위에 둔다.
신중함 편향 — 사소한 작업은 판단으로 건너뛴다.

1. **Think Before Coding (생각 먼저)** — 가정하지 않는다. 해석이 여럿이면 제시하고, 불분명하면 멈춰 묻는다.
2. **Simplicity First (단순함 우선)** — 문제를 푸는 최소 코드만. 요청 안 한 기능·추상화·유연성을 넣지 않는다.
3. **Surgical Changes (외과적 수정)** — 요청에 추적되는 줄만 고친다. 인접 코드·포맷을 "개선"하지 않는다.
4. **Goal-Driven Execution (목표 주도 실행)** — 검증 가능한 성공 기준을 정하고, 통과할 때까지 루프한다.

원문: https://github.com/forrestchang/andrej-karpathy-skills
```

블록 끝의 원문 링크는 **한 줄로 유지한다.** 링크가 있으면 전문이 필요할 때 찾아갈 수 있으므로
본문에 복제할 이유가 없어진다.

### 어디에 넣는가 — H1 바로 아래

본문의 첫 비어 있지 않은 줄이 H1(`# CLAUDE.md`, `# PayFlow` 등)이면 **그 H1 아래**에 넣는다.
H1 이 없으면 진짜 맨 위에 넣는다.

**왜 H1 위가 아닌가.** `install_agent_rules.py` 의 `retitle()` 은 첫 비어 있지 않은 줄 하나만
보고 그것이 `# CLAUDE.md` 일 때 `# AGENTS.md` 로 바꾼 뒤 즉시 멈춘다. H2 블록을 그 위에 얹으면
첫 줄이 `## Behavioral Guidelines (Karpathy)` 가 되어 제목 변환이 조용히 건너뛰어지고,
이관된 `AGENTS.md` 의 제목이 `# CLAUDE.md` 로 남는다. 에러는 나지 않는다 — 그래서 더 나쁘다.

```markdown
# CLAUDE.md              ← 그대로 둔다. 스크립트가 # AGENTS.md 로 바꾼다

## Behavioral Guidelines (Karpathy)
… (정본 블록)

## 명령                  ← 기존 /init 본문은 여기부터 그대로
```

## 3. What 과 How 분류

본문을 문단·불릿 단위로 훑어 둘로 나눈다.

### 남긴다 — What (제약)

- 빌드·테스트·린트·타입체크의 **정확한 명령** (복사해 실행할 수 있는 한 줄)
- 패키지 매니저·언어·프레임워크 제약 (`pnpm` 만 쓴다, `npm` 금지 등)
- 검증 가능한 컨벤션 (2-space 들여쓰기, strict TypeScript)
- 디렉터리 지도 한 줄 ("API 핸들러는 `src/api/handlers/`")
- Do / Don't, 건드리지 말 경로, 비밀 정보를 파일에 적지 말 것
- 코드에서 추론할 수 없는 상처·함정 (과거에 깨진 이유, 우회 근거)

### 분리 후보 — How (절차)

**이 단계에서는 파일을 만들지 않는다.** 후보로만 표시한다.

- 번호 매긴 다단계 워크플로 ("1. 고친다 2. 테스트 3. 로그 4. 커밋")
- "고치면 항상 X 하고 Y 한 뒤 Z 하라" 류 순서 지시
- 장황한 튜토리얼, `README` 를 다시 쓴 설명
- `/init` 이 코드에서 이미 읽어낼 수 있는 장문 아키텍처 해설
- 특정 경로에만 해당하는 긴 규칙 (path-scoped rule 후보)

### 리트머스

> 오타 한 줄을 고치는 대화에도 **매번** 필요한가? 아니면 그 작업을 할 때만 필요한가?

후자면 How 후보다. `CLAUDE.md`/`AGENTS.md` 는 모든 대화의 머리에 붙으므로, 가끔 쓰는 절차가
거기 있으면 매 대화가 그 토큰을 낸다.

### What 으로 남길 때의 재작성

specific · concise · structured 로 다시 쓴다.

| 원문 | 다시 쓴 것 |
|---|---|
| Format code properly | Use 2-space indentation |
| 테스트를 잘 돌려라 | 테스트: `npm test` — 커밋 전 통과 |
| 의존성 관리에 주의 | `pnpm` 만 쓴다. `npm install` 금지 |

**코드가 이미 강제하는 줄은 지운다.** 린터 설정이나 CI 가 잡아 주는 것을 문서에 또 적으면
지시만 길어지고 준수율은 오르지 않는다.

## 4. 분리 승인 게이트 (필수)

How 후보가 **하나라도** 있으면 설치 스크립트를 호출하기 전에 표를 보여 승인을 받는다.

| 후보 ID | 원문 발췌 (최대 8줄) | 제안 목적지 | 남는 What 한 줄 | 200줄 영향 |
|---|---|---|---|---|
| H1 | `1. 브랜치를 판다 …` (8줄) | 프로젝트 `SKILL.md` (`.claude/skills/release-flow/`) | `릴리스는 /release-flow 로 한다` | −24 |
| H2 | `src/api/** 는 …` (5줄) | `.claude/rules/api-conventions.md` + `paths:` | `API 규약은 .claude/rules/api-conventions.md` | −4 |

### 목적지 규칙

- **절차·순서** → 프로젝트 `SKILL.md`. 필요할 때만 로드되므로 상시 비용이 0 이다.
  **`git-branch-workflow` 에 이어 붙이지 않는다** — 그 파일은 이 스킬이 템플릿에서 다시 렌더하므로
  재설치 때 사라진다.
- **특정 glob 에만 해당하는 규칙** → `.claude/rules/<name>.md` 에 `paths` frontmatter.
  always-on 규칙으로 올리지 않는다 — 한 디렉터리 규칙을 전 대화에 물리는 것은 200줄 예산의
  가장 흔한 누수다.
- **목적지가 애매하면** 기본 권고는 "What 한 줄로 축약하고 절차는 버린다" 다.
  스킬/rules 신설은 선택지로만 제시한다. 안 읽히는 파일을 늘리는 것보다 낫다.

### 사용자가 고르는 세 갈래

| 선택 | 결과 |
|---|---|
| **승인** | 그 후보에 대해서만 그 때 파일을 만든다. 승인 범위 밖 파일은 만들지 않는다 |
| **축약만** | How 를 지우고 What 한 줄만 남긴다. 새 파일을 만들지 않는다 |
| **보류** | 그 구간을 이관 본문에 그대로 남긴다. 200줄 초과 위험이 있으면 그 사실을 함께 알린다 |

**침묵은 거절이 아니다.** 답이 올 때까지 파일을 만들지 않고 기다린다.
거절·무응답 상태에서 후보를 삭제하거나 파일을 만들지 않는다.

## 5. 200줄 예산 계산

측정 대상은 **이관 후 `AGENTS.md` 전체 줄 수** 다.

| | 항목 |
|---|---|
| 포함 | 카파시 짧은 블록 · 다듬은 `/init` 본문 · 규칙 **포인터 마커 블록** (`<!-- >>> agent-rules: … >>> -->`. 마커는 포인터라 짧다) |
| 제외 | `.claude/rules/*.md` 규칙 본문 · `.cursor/rules/*.mdc` · 새로 승인된 `SKILL.md` |

Step 0.5 끝에서 예상 줄 수를 사용자에게 보여 준다. 200 이상이면 더 자를 What 이나 추가 분리
후보를 제안하고 **다시 승인**받는다. **200줄을 넘긴 채 스크립트를 돌리지 않는 것이 기본이다.**
사용자가 "이대로 이관" 을 명시하면 진행하되, 설치 보고에 줄 수와 목표 미달을 적는다.

손으로 센 값은 어긋난다. `install_agent_rules.py --dry-run` 이 마커 블록까지 반영한
**예상 줄 수**를 출력하므로, 승인 직전 숫자는 그 출력을 쓴다.

## 6. 재실행과 옵트아웃

**포인터 구조로 재실행하는 경우** (`CLAUDE.md` 에 `@AGENTS.md` 가 있고 `AGENTS.md` 존재)
Step 0.5 의 대상은 `AGENTS.md` 본문이다. **포인터 파일에는 카파시 본문을 넣지 않는다** —
`CLAUDE.md` 에 내용이 다시 들어가면 `check-agent-rules` 검사 3 이 실패하고, 무엇보다
Cursor 가 그것을 못 읽어 두 도구의 지시가 갈라진다.

**사용자가 "다듬지 말고 그대로 옮겨줘" 라고 명시하면** Step 0.5 를 통째로 건너뛴다.
사용자 지시가 스킬 절차보다 우선한다. 이때도 설치 보고에는 `AGENTS.md` 줄 수와 200줄 목표
미달 여부를 남긴다 — 나중에 다듬을 근거가 되기 때문이다.
