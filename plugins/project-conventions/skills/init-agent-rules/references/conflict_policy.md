# 기존 AGENTS.md 충돌 처리

`AGENTS.md` 가 이미 있고 포인터 구조가 아니면 설치 스크립트가 exit 3 으로 멈춘다. 이 문서는
그 이후의 절차다.

## 왜 자동 병합하지 않는가

두 파일에 같은 주제의 지시가 다르게 적혀 있을 때, 어느 쪽이 최신인지는 파일 내용만으로
판정할 수 없다. 모델이 고르면 반드시 틀리는 경우가 생기고, 틀린 결과는 규칙 문서에 남아
이후 모든 세션의 전제가 된다. 잘못 합친 규칙은 없는 규칙보다 나쁘다.

그래서 이 스킬은 **판단을 사용자에게 넘긴다.** 대신 판단에 필요한 재료 — 두 파일의 실제 차이 —
를 정확하게 제시한다.

## Step 1. 차이를 보여준다

두 파일의 섹션(H2) 목록을 뽑아 세 갈래로 분류한다.

```bash
diff <(grep '^## ' CLAUDE.md) <(grep '^## ' AGENTS.md)
```

사용자에게 이 형식으로 보고한다:

```
`AGENTS.md` 가 이미 있습니다. 두 파일의 섹션을 비교했습니다.

| 섹션 | CLAUDE.md | AGENTS.md |
|---|---|---|
| 명령 | ✓ | ✓ |   ← 양쪽에 있음. 내용이 다를 수 있음
| 구조 | ✓ | — |
| 코딩 규칙 | — | ✓ |

양쪽에 있는 섹션: {목록}
→ 이 섹션들의 본문이 실제로 다른지 확인이 필요합니다.
```

양쪽에 있는 섹션은 본문까지 비교해 실제로 다른 것만 짚어 준다. 섹션명이 같다는 이유만으로
"충돌"이라고 보고하면 사용자가 확인할 게 늘어나기만 한다.

## Step 2. 선택지를 제시한다

| 선택 | 스크립트 인자 | 결과 |
|---|---|---|
| **abort** (기본) | — | 아무것도 바꾸지 않고 종료. 사용자가 손으로 정리한 뒤 다시 부른다 |
| **append-claude** | `--on-existing-agents append-claude` | 기존 `AGENTS.md` 를 그대로 두고 그 뒤에 `CLAUDE.md` 본문을 주석 구분선과 함께 이어붙인다. 중복·모순은 남으므로 **사용자가 이어서 정리해야 한다** |
| **keep-agents** | `--on-existing-agents keep-agents` | 기존 `AGENTS.md` 를 정본으로 삼고 `CLAUDE.md` 본문은 폐기한다 |

기본값은 `abort` 다. 사용자가 명시적으로 고르지 않으면 아무것도 하지 않는다.

## Step 3. 선택별 후속 처리

### append-claude 를 골랐을 때

이어붙인 직후의 `AGENTS.md` 는 **중복 섹션이 그대로 남아 있는 상태**다. 에이전트가 모순된
지시를 읽게 되므로 방치하면 안 된다. 설치 완료 보고에 이 문장을 반드시 포함한다:

> `AGENTS.md` 에 두 문서가 이어붙어 있습니다. 중복 섹션 {목록} 을 정리해야 합니다.
> 지금 정리를 도와드릴까요?

사용자가 원하면 이어서 정리한다. 정리는 별도 작업이며, 이 스킬의 설치 단계와 섞지 않는다.

### keep-agents 를 골랐을 때

`CLAUDE.md` 본문이 사라진다. 스크립트는 `CLAUDE.md` 가 커밋된 상태가 아니면 exit 3 으로
거부한다 — 커밋돼 있어야 git 히스토리로 되돌릴 수 있기 때문이다.

사용자가 그래도 진행하겠다고 하면 `--force` 를 붙인다. 이때는 폐기될 내용을 먼저 보여주고
확인받는다.

## 재실행인 경우는 충돌이 아니다

`CLAUDE.md` 가 이미 `@AGENTS.md` 포인터이고 `AGENTS.md` 가 있으면 이 스킬을 이미 한 번
실행한 것이다. 이때는 충돌 처리로 가지 않고 규칙 파일 재생성과 마커 블록 교체만 수행한다.
스크립트가 이 상태를 스스로 판별하므로 별도 인자가 필요 없다.
